## Описание проекта

Приложение представляет собой каталог учебных курсов. Пользователь может просматривать список курсов, фильтровать его по преподавателю, добавлять, редактировать и удалять записи. Данные хранятся в файле `data/courses.db` и сохраняются между перезапусками сервера.

Проект использует Node.js, Express и встроенный модуль `node:sqlite`, который предоставляет API для работы с SQLite. Поэтому отдельную библиотеку SQLite устанавливать не нужно. HTML, CSS и клиентский JavaScript находятся в папке `public`, серверные маршруты и функции доступа к данным разделены по модулям.

## Используемые технологии

- **Node.js** — среда выполнения JavaScript.
- **Express** — HTTP-сервер и маршруты REST-подобного API.
- **SQLite** — реляционная база данных в одном файле.
- **node:sqlite** — встроенный модуль Node.js для подключения к SQLite и выполнения SQL-запросов.
- **HTML, CSS и JavaScript** — пользовательский интерфейс.

## Структура базы данных

Создаются две таблицы.

### `teachers`

| Поле | Тип | Описание |
|---|---|---|
| `id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | Идентификатор преподавателя |
| `full_name` | `TEXT NOT NULL` | ФИО преподавателя |

### `courses`

| Поле | Тип | Описание |
|---|---|---|
| `id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | Идентификатор курса |
| `course_name` | `TEXT NOT NULL` | Название курса |
| `teacher_id` | `INTEGER NOT NULL` | Внешний ключ на `teachers.id` |
| `credits` | `REAL NOT NULL` | Положительное количество кредитов |

Имя преподавателя не дублируется в таблице `courses`. Для отображения имени используется SQL `JOIN`, а сама связь задаётся полем `teacher_id` и внешним ключом. Для SQLite включена проверка внешних ключей.

## Запуск проекта

### 1. Установить инструменты

Установи актуальную LTS-версию Node.js с официального сайта: <https://nodejs.org/>. Для встроенного модуля `node:sqlite` нужна Node.js версии 22.13.0 или новее; рекомендуется актуальная Node.js 24 LTS. Вместе с Node.js устанавливается npm. Отдельно устанавливать SQLite или её npm-пакет не нужно.

Проверь установку в терминале:

```powershell
node -v
npm -v
```

### 2. Установить зависимости

Открой терминал в корневой папке проекта — там, где находятся `server.js` и `package.json` — и выполни:

```powershell
npm install
```

### 3. Запустить сервер

```powershell
npm start
```

В терминале появятся сообщения о запуске сервера и готовности базы данных. Открой в браузере <http://localhost:3000>.

Для перезапуска сервера при изменениях можно использовать команду:

```powershell
npm run dev
```

## API-маршруты

Базовый адрес API: `http://localhost:3000`.

| Метод | Адрес | Назначение |
|---|---|---|
| `GET` | `/api/status` | Состояние сервера и количество записей |
| `GET` | `/api/teachers` | Получение списка преподавателей |
| `GET` | `/api/courses` | Получение всех курсов |
| `GET` | `/api/courses?teacher_id=3` | Получение курсов выбранного преподавателя |
| `POST` | `/api/courses` | Создание курса |
| `PUT` | `/api/courses/:id` | Обновление курса по ID |
| `DELETE` | `/api/courses/:id` | Удаление курса по ID |

### Пример ответа `GET /api/courses`

```json
[
  {
    "id": 1,
    "course_name": "Web-технологии",
    "teacher_id": 1,
    "teacher_name": "Иванов Иван Иванович",
    "credits": 4
  }
]
```

Поле `teacher_name` формируется через SQL `JOIN` и не хранится в таблице `courses`.

### Создание курса — POST

Адрес: `POST http://localhost:3000/api/courses`  
Тело запроса (`Content-Type: application/json`):

```json
{
  "course_name": "Основы веб-разработки",
  "teacher_id": 2,
  "credits": 3
}
```

Успешное создание возвращает HTTP `201 Created` и объект созданного курса.

### Обновление курса — PUT

Адрес: `PUT http://localhost:3000/api/courses/1`  
В теле передаются поля `course_name`, `teacher_id` и `credits`:

```json
{
  "course_name": "Web-технологии (обновлённый курс)",
  "teacher_id": 1,
  "credits": 5
}
```

### Удаление курса — DELETE

Адрес: `DELETE http://localhost:3000/api/courses/1`.

## Проверка API в PowerShell

Команды ниже подходят для терминала PowerShell в Windows. Перед проверкой сервер должен быть запущен в другом окне терминала.

Получить все курсы:

```powershell
Invoke-RestMethod -Uri "http://localhost:3000/api/courses"
```

Получить курсы преподавателя с ID 3:

```powershell
Invoke-RestMethod -Uri "http://localhost:3000/api/courses?teacher_id=3"
```

Создать курс:

```powershell
$body = @{
    course_name = "Тестовый курс"
    teacher_id = 1
    credits = 3
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://localhost:3000/api/courses" `
    -Method Post `
    -ContentType "application/json" `
    -Body $body
```

Обновить курс с ID 1:

```powershell
$body = @{
    course_name = "Обновлённый курс"
    teacher_id = 1
    credits = 4
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://localhost:3000/api/courses/1" `
    -Method Put `
    -ContentType "application/json" `
    -Body $body
```

Удалить курс с ID 1:

```powershell
Invoke-RestMethod -Uri "http://localhost:3000/api/courses/1" -Method Delete
```

## Валидация и обработка ошибок

- Пустое `course_name` → HTTP `400 Bad Request`.
- `teacher_id` должен быть положительным целым числом и ссылаться на существующего преподавателя → иначе HTTP `400`.
- `credits` должно быть положительным числом → иначе HTTP `400`.
- Если курс с указанным ID не найден, при `PUT` и `DELETE` возвращается HTTP `404 Not Found`.
- При неизвестном API-маршруте возвращается JSON с HTTP `404`.

SQL-запросы выполняются через подготовленные выражения с параметрами. Это помогает избежать подстановки пользовательского ввода непосредственно в SQL-код. В Node.js 22.13–24.14 может выводиться `ExperimentalWarning` для встроенного модуля SQLite; это предупреждение о статусе API Node.js, а не ошибка проекта. В актуальной Node.js 24.15+ модуль имеет статус Release Candidate.
